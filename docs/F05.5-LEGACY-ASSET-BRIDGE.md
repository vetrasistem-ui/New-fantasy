# F05.5 — TFS 1.4.2 / 10.98 Map Compatibility + Real Map Bootstrap

Status: **IN PROGRESS / REALIGNED**

Branch: `feature/f05.5-pokefans-1098`

## Objetivo

Homologar o Fantasy Studio V5 como Map Editor real para a baseline **TFS 1.4.2 / protocolo 10.98**, usando OTBM v3, DAT, SPR e OTB reais.

Primeiro projeto de teste/homologação: **PokeFans/PokeJornadas 10.98**.

```text
PokeFans 10.98
├── map .otbm
├── Tibia.dat
├── Tibia.spr
├── items.otb
├── map-house.xml
└── map-spawn.xml
        ↓
Fantasy 10.98 compatibility core
├── DAT reader
├── SPR reader
├── OTB reader
├── OTBM reader/writer
└── houses/spawns support
        ↓
Fantasy Studio V5
        ↓ save
OTBM v3 + XML auxiliares
        ↓
TFS 1.4.2 vanilla
        ↓
Protocol 10.98
        ↓
Client 10.98
```

## Mudança de direção

Nesta baseline:

- **TFS 1.4.2 é o servidor/runtime oficial atual**;
- **10.98 é o protocolo oficial atual**;
- **OTBM v3 é o formato de mapa operacional atual**;
- DAT/SPR/OTB 10.98 são formatos ativos da compatibilidade atual, não apenas material de migração;
- BlackTek MapEditor é a principal referência de comportamento do Map Editor 10.98;
- RME 3.7 fica como referência secundária;
- a UI do produto continua sendo o Fantasy Studio V5 em SDL3 + SDL_Renderer3 + Dear ImGui.

FMAP, Fantasy Server e Fantasy Protocol próprios ficam preservados como experimentos anteriores, mas não são o caminho obrigatório desta fase.

## Regra de implementação

O New Fantasy deve possuir implementação própria e testável para o caminho 10.98.

BlackTek/RME podem ser usados para:

- observar comportamento;
- comparar resultados;
- validar estrutura de mapa/assets;
- servir como oráculo de brushes, palette, houses, spawns e Undo/Redo.

Não copiar código-fonte BlackTek/RME para o core enquanto a estratégia de licença não estiver explicitamente resolvida.

## Extensões BlackTek fora da baseline inicial

Não incorporar automaticamente:

- Zone IDs;
- Zone Brush;
- arquivos TOML de zonas;
- attribute-map OTBM 128;

- qualquer dependência específica do BlackTek Server que não seja aceita pelo TFS 1.4.2 vanilla.

Esses recursos podem ser estudados depois como extensões Fantasy/TFS, sempre por decisão separada.

## Asset resolution

Fluxo oficial de resolução visual:

```text
OTBM serverId
      ↓
items.otb
serverId → clientId
      ↓
Tibia.dat
clientId → appearance/frame/sprite IDs
      ↓
Tibia.spr
sprite ID → pixels
      ↓
SDL texture/cache
      ↓
Fantasy Studio V5
```

Falhas nunca podem desaparecer silenciosamente. O Studio deve reportar:

- server ID sem entrada OTB;
- client ID sem appearance DAT;
- sprite ID ausente/inválido;
- atributo OTBM não suportado;
- node OTBM desconhecido;
- house/spawn inválido.
