# F05.5 — Legacy Asset Bridge (DAT / SPR / OTB)

Status: **PREPARED / NOT STARTED**

## Objetivo

Colocar sprites reais no Fantasy Map Editor e no Fantasy Client agora, reutilizando um pacote DAT + SPR + OTB fornecido pelo usuário/projeto, sem recriar todo o conteúdo visual do zero e sem transformar formatos legados no contrato permanente do Fantasy.

## Princípio

```text
DAT + SPR + OTB
       ↓
Legacy Asset Bridge
       ↓
Fantasy Asset Registry
       ↓
semantic keys
       ↓
Studio + Client
```

O FMAP continua independente. Chaves semânticas Fantasy permanecem o contrato do mapa e da lógica de alto nível.

## Responsabilidades do bridge

- abrir e validar o conjunto DAT/SPR/OTB configurado para o projeto;
- extrair sprites e metadados necessários para visualização;
- associar IDs legados a chaves semânticas Fantasy;
- expor uma API neutra para Studio e Client;
- reportar asset ausente/inválido sem corromper o mapa;
- manter paths relativos ao projeto;
- não espalhar parsing DAT/SPR/OTB pelo Editor, Client ou WorldRuntime.

## Escopo MVP

1. `LegacyAssetSource` para carregar o conjunto configurado.
2. `FantasyAssetRegistry` compartilhado.
3. Cache de sprites/frames necessários ao mapa visível.
4. Render de ground real no Studio.
5. Render de objects reais no Studio.
6. Palette mínima navegável no Studio.
7. Mesmo registry no Fantasy Client.
8. Placeholder determinístico para asset ausente.
9. Save/Reopen preserva apenas semântica FMAP; não serializa textura/cache.
10. Testes automatizados do registry/mapeamento e teste visual Windows.

## Fora do escopo

- reescrever os assets em formato nativo definitivo;
- atlas/packing definitivo;
- remasterização de sprites;
- animação avançada, shaders ou lighting;
- migração massiva de todos os assets;
- editor completo de items/monsters;
- alterar Fantasy Protocol para carregar pixels de sprite.

## Configuração esperada

O projeto deverá apontar para arquivos legados por caminhos relativos/configuráveis, por exemplo:

```text
Game/Assets/Legacy/client.dat
Game/Assets/Legacy/client.spr
Game/Assets/Legacy/items.otb
```

Esses nomes são exemplos. O bridge não deve depender de um nome físico fixo.

Arquivos binários legados não devem ser adicionados ao repositório quando não houver autorização de redistribuição. O usuário fornece o conjunto localmente.

## Gates de conclusão

- conjunto DAT/SPR/OTB abre e é validado;
- ao menos ground, border e object são resolvidos pelo registry;
- Studio renderiza sprites reais em vez de quadrados para assets mapeados;
- palette permite selecionar e pintar pelo menos um ground e um object;
- Save/Reopen mantém o resultado semanticamente;
- Client renderiza o mesmo mapa usando o mesmo registry;
- asset ausente usa placeholder e não derruba Studio/Client;
- build/testes F00–F05 continuam verdes;
- validação visual real no Windows registrada em evidência.

## Relação com F13

F05.5 é um bootstrap visual. A F13 continua responsável pelo Asset Pipeline completo: importação/migração avançada, formato nativo definitivo, atlas, animações, efeitos, ferramentas de assets e substituição gradual do legado.
